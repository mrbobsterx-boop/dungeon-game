# Архитектура

## Принцип

Игровая логика (генерация подземелий, бой, инвентарь, ИИ, прогрессия) отделена от:
1. слоя рендеринга (Canvas сейчас, может стать WebGL/движок позже);
2. слоя сети (сервера может не быть — singleplayer работает автономно локально).

Это достигается через модуль `systems/` + `entities/`, построенные по облегчённой
ECS-модели (Entity-Component-System): у сущности (Entity) есть набор компонентов-данных
(Position, Health, Inventory, AI...), а логика живёт в системах, которые эти компоненты
обрабатывают каждый тик. Замена рендерера или добавление сети не трогает системы.

## Клиент (client/)

```
src/
├── core/        # game loop, менеджер состояний (меню/игра/пауза), шина событий
├── rendering/    # Canvas-рендерер, камера, освещение/туман войны, спрайты
├── world/        # процедурная генерация этажей, биомы, тайлмап, fog of war
├── entities/     # Entity + компоненты, игрок, монстры, NPC
├── items/        # предметы, экипировка, таблицы дропа, источники света
├── systems/      # бой, движение, инвентарь, крафт, прогрессия, квесты
├── ui/           # HUD, инвентарь, персонаж, навыки, квесты, торговец, меню (без карты — см. docs/UI_SPEC.md)
├── audio/        # звук и музыка
├── network/      # клиент будущего мультиплеера (пока не используется)
├── data/         # балансировочные JSON-таблицы (монстры, предметы, биомы, скиллы)
└── utils/        # seeded RNG, pathfinding, математика
```

### Освещение и туман войны

`rendering/LightingSystem.js` считает видимую область вокруг источников света
(фонарь игрока + прочие источники) и передаёт маску в `world/FogOfWar.js`,
который хранит per-tile состояние: "неизведано / было видно / видно сейчас".
Радиус и качество света зависят от экипированного источника света (`items/LightSources.js`).

### Процедурная генерация

`world/dungeon/DungeonGenerator.js` — генерирует этаж по seed:
1. выбирает биом (`biomes/Labyrinth.js`, `Cave.js`, `Ruins.js`, `Mines.js`, ...);
2. раскладывает комнаты/коридоры/пещеры по алгоритму биома;
3. расставляет монстров, лут, ловушки, торговцев, секретные комнаты, шахты/лестницы/лифты между этажами.

Каждый этаж воспроизводим по seed — важно для будущих совместных/соревновательных механик.

## Сервер (server/, Java/Spring Boot)

Не обязателен для одиночной игры. Отвечает за:
- аккаунты и аутентификацию (`security/`, `controller/AuthController.java`)
- облачные сохранения (`service/SaveGameService.java`, `controller/SaveController.java`)
- лидерборды/статистику забегов
- в будущем: realtime-сессии мультиплеера через `websocket/GameSessionHandler.java`

### UI и статы персонажа

Подробная структура экранов (HUD, инвентарь, персонаж, навыки, квесты, меню),
модель атрибутов/боевых характеристик/сопротивлений и слоты экипировки —
см. [`docs/UI_SPEC.md`](UI_SPEC.md). Ключевое правило: вторичные характеристики
всегда считает `systems/StatsSystem.js`, экраны UI только отображают готовый снапшот.

## shared/

JSON-схема формата сохранения и описание сетевого протокола — единый источник правды
для клиента и сервера, чтобы они не расходились по формату данных.
